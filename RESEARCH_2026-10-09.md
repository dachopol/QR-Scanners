# QR Scanners — Research Verification (2026-10-09)

Scope: Android / Google Play requirements that materially affect QR Scanners production readiness.

## Verified official requirements

1. **Target API**
   - Google Play requires new apps and app updates submitted from 31 Aug 2026 to target Android 16 / API 36 or higher.
   - QR Scanners source currently targets API 36.
   - Official: https://support.google.com/googleplay/android-developer/answer/11926878

2. **Nearby Wi-Fi permission**
   - Apps targeting Android 13 / API 33+ that manage Wi-Fi connections should request `NEARBY_WIFI_DEVICES` at runtime.
   - QR Scanners uses `WifiNetworkSpecifier`; the missing permission path was fixed in commit `1d0f87e95f5ee0a8c43e7253439393326107c9a9`.
   - CI run `37279618439` passed after the fix. Physical Android 13+ regression remains required.
   - Official: https://developer.android.com/develop/connectivity/wifi/wifi-permissions

3. **16 KB page-size compatibility**
   - Google Play requires apps targeting Android 15 / API 35+ to support 16 KB memory page sizes on 64-bit devices; updates that fail this requirement will be blocked from 1 Feb 2027.
   - QR Scanners CI already runs `zipalign -c -P 16` and the current release gate records PASS.
   - Official: https://developer.android.com/guide/practices/page-sizes

4. **Closed testing for eligible new personal accounts**
   - Production access requires at least 12 testers opted into a closed test continuously for at least 14 days.
   - QR Scanners has not yet verified completion of this gate.
   - Official: https://support.google.com/googleplay/android-developer/answer/14151465

## Research conclusion

The current source meets the API-level and automated 16 KB build gates. The Android 13+ Nearby Wi-Fi permission defect has been fixed and passes CI, but requires physical-device verification. Production remains blocked by the applicable closed-test requirement and by any planned production ads/Ad-Free configuration until real IDs/products and updated Play declarations are verified.

No fake IDs, fabricated tester evidence, or synthetic production results may be used.


## Future migration note — Android 17 / target API 37

Android 17 enforces local-network protection for apps that target API 37 or higher and introduces `ACCESS_LOCAL_NETWORK` for broad local-network access. QR Scanners currently targets API 36, so this is **not a current permission requirement** and must not be added speculatively.

Before any future targetSdk 37 migration:
1. Re-evaluate the Wi-Fi QR connection flow against Android 17 local-network policy.
2. Prefer system-mediated/privacy-preserving APIs where applicable.
3. Add `ACCESS_LOCAL_NETWORK` only if the actual future feature path requires it.
4. Re-run permission, Data Safety, Wi-Fi association and physical-device regression.

Official reference:
https://developer.android.com/privacy-and-security/local-network-permission
